# X（原 Twitter）拼接 / 多分割图像自动还原 (Connected Images)

在 X（原 Twitter）上，把一张高分辨率插画最多拆成 4 张发布已是广泛流行的做法。  
MangaMeYeah! 会通过高级图像相关性分析自动识别这些被分割发布的连续图像，并把它们合并还原为原本的一张大图显示。

---

## 1. 支持的分割模式

| 模式 | 网格 | 特点与用途 |
| :--- | :---: | :--- |
| **横向 2 张拼接** (跨页) | 2 列 × 1 行 | 横向宽幅插画或跨页漫画 |
| **纵向 2 张拼接** | 1 列 × 2 行 | 纵向全身插画或四格漫画 |
| **横向 3 张拼接** | 3 列 × 1 行 | 横向全景 / 页眉图像 |
| **纵向 3 张拼接** | 1 列 × 3 行 | 纵向长条滚动漫画 |
| **横向 4 张拼接** | 4 列 × 1 行 | 超宽全景插画 |
| **纵向 4 张拼接** | 1 列 × 4 行 | 纵向长幅角色设定图、服装介绍等 |
| **2×2 拼接** (4 张组) | 2 列 × 2 行 | X（Twitter）标准的 4 图网格发帖 |

## 2. 24 种全排列还原算法

### 时间线上刻意调整顺序导致的错乱问题
在 X（Twitter）上，为了让时间线里看起来像另一张图、或制造意外与视觉错觉，有人会在上传图像后用帖子编辑功能刻意改变图像排列顺序再发布。  
这样一来，下载得到的文件名连续编号（上传顺序等）与插画本应正确拼接的位置（`[左上, 右上, 左下, 右下]`）就会出现错位，按文件名顺序排列时画面会七零八落。

MangaMeYeah! 会对 4 张图像**瞬间生成 $4! = 24$ 种全部排列**，并在毫秒级内穷举比对以下拼接接缝（边界）的色差与相关性：
- 左上 与 右上 的拼接边界
- 左下 与 右下 的拼接边界
- 左上 与 左下 的拼接边界
- 右上 与 右下 的拼接边界

由于会自动选出拼接误差（MAE）最小、相关性最高的组合来排布，**即使是为时间线效果而刻意打乱顺序的图像，也能自动还原到原本正确的位置**。

## 3. 误检防止过滤器（应对白边与纯色背景）

### 为什么会发生误检？
当蓝天、海面、纯白摄影棚背景等背景均匀的图像连续排列时，如果只简单比较边缘（边界）的色差，即使是完全无关的两张图，也会被判为「色差接近零」而误判为可拼接。

### MangaMeYeah! 的防护架构
1. **拼接接缝的边缘色彩标准差 (`seamStdDev >= 7.0`)**:
   纯白或纯色留白框等没有纹理与色彩变化的接缝，会被判定为「不是应当拼接的画面」并立即排除。由此彻底杜绝了白背景单张插画被误识别为横向 2 张或 4 张的现象。
2. **横纵双向评分**:
   对正方形或等尺寸的分割图像（例如纵向 4 张的服装设定表），会同时计算横向与纵向的接缝质量分数并比较，优先采用画面真正连续的方向（纵向分割）。
3. **跨页偏移自动修正**:
   在双页（跨页）显示途中遇到拼接图像的起始位置时，为避免前一张图把拼接图像的第一张卷进来造成分断，会把前一页自动切换为单页以消除位置偏移。

## 4. 拼接图像检测的开 / 关设置（持久化）

- **从菜单即时切换**:
  点击主菜单或右键菜单中 **`视图(_V)` 最下方的 `拼接图像检测(_C)`**，可随时立即开启 / 关闭。
- **设置持久保存**:
  切换后的状态会立即写入 `MangaMeYeah.ini` 的 `AutoDetectConnectedImages`，下次启动时保持。
- **关闭检测时的行为**:
  关闭拼接图像检测后，后台图像分析与询问对话框会被完全抑制，所有图像都按常规单页或跨页方式高速浏览。

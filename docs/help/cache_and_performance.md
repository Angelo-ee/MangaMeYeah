# 缓存机制与性能调优 (Cache & Performance)

MangaMeYeah! 内置了高效的按需缓存与异步预加载引擎，即使是容量庞大的图像文件夹或巨型压缩包文件，也能做到翻页零等待。

---

## 1. 两套相互独立的缓存架构

MangaMeYeah! 的缓存系统明确区分为 **主视图用** 与 **缩略图列表用** 两套。

```
[磁盘/压缩包]
    │
    ├─► (浏览时) ──► 主视图缓存 (PageCacheEngine)
    │                 ├─ 原始尺寸 / 按画面优化的解码位图
    │                 ├─ 解码缓存数 (默认 32 张)
    │                 └─ 缓存容量上限 (默认 2048 MB)
    │
    └─► (列表时) ──► 缩略图缓存 (ThumbnailItemViewModel)
                      ├─ 约 220px 的轻量缩放图像
                      └─ 完全不占用主视图的 32 张缓存额度
```

### 为什么要分离？
一般的浏览器中，打开缩略图列表并载入几百张缩略图后，刚读到的主视图高画质位图会被挤出内存，返回主视图时就会因重新解码而卡顿。  
MangaMeYeah! 把缩略图直接保存在与主视图缓存分离的轻量视图模型侧，因此**即使一次载入几千张缩略图，主视图前后页（32 张额度）也不会被丢弃，极速翻页性能完全不受影响**。

## 2. 缓存设置项与调优

以下是 `工具(_T) > 设置(_C)...` 中「缓存设置」标签页里各项的含义与推荐值。

### 解码缓存数 (默认: 32 张)
- **含义**: 在内存中保留已解码的无压缩位图图像的最大张数。
- **推荐**: 日常使用 **32 ~ 64 张** 已足够流畅。如果习惯频繁前后反复翻阅，可根据内存容量提高到 128 张等，体验会更顺滑。

### 启用缩放缓存 (默认: 开)
- **含义**: 开启时，会按显示器分辨率缓存经过优化缩小的位图。
- **效果**: 浏览 4K~8K 等超高分辨率插画时，可大幅降低内存占用并减轻 GPU 绘制负担。

### 预加载数（前进方向 / 后退方向）(默认: 4~6 张)
- **含义**: 从当前浏览页出发，提前在后台完成解码的张数。
- **要点**:
  - **启用自动拼接图像检测时**: 为检测 X（原 Twitter）的 4 分割图像或 2×2 图像，请把 **前进方向的预加载数设为「4 张以上」**（默认已设为 4 张以上）。

### 预加载线程优先级 (默认: 2 通常)
可用滑块在 0（最低）~ 4（最高）共 5 档之间指定。

| 级别 | 优先级名称 | 特点与推荐用途 |
| :---: | :--- | :--- |
| **0** | **最低** (Lowest) | 最优先保障 UI 线程（鼠标操作与动画）。适合想压低 CPU 负载的节能笔记本，或边玩游戏边在后台浏览。 |
| **1** | **较低** (BelowNormal) | 在确实不干扰阅读操作的前提下平滑预加载。 |
| **2** | **通常** (Normal) ★推荐 | 适合一般多核 PC，预加载与 UI 的平衡最佳。 |
| **3** | **较高** (AboveNormal) | 快速滚动时希望预加载更超前时有效。 |
| **4** | **最高** (Highest) | 投入最大 CPU 资源，以极限速度把下一页展开到内存。 |

### 缓存容量上限 (默认: 2048 MB)
- 当缓存整体的合计预估内存用量超过该上限（例如 2GB）时，会从距离当前浏览位置最远的旧缓存开始自动垃圾回收（LRU 淘汰）。
- 指定为 `0 MB` 表示不限制内存。
